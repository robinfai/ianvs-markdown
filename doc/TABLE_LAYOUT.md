# Markdown 表格列宽

默认阅读态和 Live Preview 采用相同的内容感知分配规则：

- 同时考虑表头与正文，按可见文本和行内代码/强调字体测量；链接使用显示标签，计入文件 chip / 外链图标的附加宽度，不用隐藏 URL 撑宽列。
- ID、状态、数值等短列保持紧凑；长描述优先使用可用空间。短表不强行拉满正文宽度。
- 长文本的首选宽度有上限（36 em 加单元格内边距），窄视口按各列可压缩空间同比收缩。
- 长列保留约 8 em 的可读宽度；短列以内容宽度为准。所有最小宽度之和超过视口时，表格横向滚动，不把多列强挤到同一屏；大文字模式下单列的可读下限若超过视口，先限制到视口宽度，确保焦点列仍能完整进入屏幕。
- 字体、字重与系统文字缩放参与测量；Live 额外预留文本编辑器的光标间隙，避免短词多换一行。RTL 使用相同的逻辑列顺序和原有对齐；左、中、右对齐不改变。
- Live Preview 的单元格、增删/移动操作柄随表格一起滚动；键盘切换焦点会把目标单元格带入可见区域。原始 Markdown、选区和导出语义不改变。

首选宽度只在可见内容或排版配置变化时测量，窗口缩放和焦点切换复用结果。测量缓存按表格局部管理，不超过 256 个标签；超过 256 个 UTF-16 码元的超长标签直接使用宽度上限，实际渲染文字不截断。布局使用固定列宽，避免每次 Table 布局重新遍历全部单元格进行固有尺寸测量。

宿主通过 `MarkdownStyleSheet.tableColumnWidth` 显式指定的 `FixedColumnWidth`、`FlexColumnWidth` 或 `IntrinsicColumnWidth` 保持原行为。自定义单元格 builder 若提供非文本控件或特别的尺寸约束，可继续选用宿主列宽策略。HTML 表格和 HTML 导出不在此次变更范围内。

## 回归场景

`test/adaptive_table_layout_test.dart` 覆盖分配边界、短列与长描述、长表头、中英文、URL/行内代码、窄屏多列、文字缩放、RTL、键盘焦点与显式宿主策略。`test/table_width_test.dart` 和既有 Live / 链接测试继续检查编辑、单元格边界、行高与来源保持。

人工检查可打开 `test/fixtures/table_width_scenarios.md`，分别切换 Reading / Live，调整到 320、480、720、1000 px，并开启 2× 系统文字缩放。检查横向滚动、最后一列的点击/Tab、移动列操作柄，以及长链接换行后的下一行边界。

可选截图工具：`flutter test --no-pub tool/capture_table_layout.dart --reporter expanded`。
它在 `build/table-layout/` 生成真实 Flutter 阅读/编辑组件的 PNG 与几何记录，不是
浏览器模拟或原生设备验收；请按工具顶部说明准备其截图字体。核心回归测试自带
小型比例字体与许可证，不依赖可选 Mermaid 后端或系统字体。
