# iOS 模拟器实际操作验收 · 2026-11-02

设备：iPhone 16 Plus，iOS 18.4。通过 Xcode Device Hub 操作实际运行的应用，使用点击、长按、屏幕键盘、滚动及横竖屏切换。发现问题后重新构建、安装并复测，未以测试通过代替界面验收。

## 实际完成的流程

| 流程 | 结果 |
| --- | --- |
| 新建目录 → 重命名 → 复制 → 移入子目录 → 展开 | 完成；目录变化可见，无需重启 |
| 子目录中新建 Markdown → 屏幕键盘输入 → 保存 → 再次打开 | 内容 `qa` 保留；打开文件后抽屉关闭 |
| 文件移到最近删除 → 展开回收目录 → Move to… 恢复 → 再次打开 | 内容完整，显示 Saved locally |
| 系统 Choose Other Folder… → 选择本机 Linefold 目录 → 确认移动 | `qa.md` 从 QA 子目录移至 Documents；QA 工作区保持不变；原位置消失，目标内容核对为 `qa` |
| 删除测试目录 → 展开最近删除 | 自动刷新，显示可读日期目录；目录可恢复 |
| 冲突提示 → 比较差异 → 选择云端版本 | 主文件采用选中内容，原磁盘内容保存为独立副本，提示消失 |
| 冲突提示 → 全部保留 | 主文件及其他版本均保留，提示消失 |
| 屏幕键盘修改但未保存 → 使用当前编辑解决冲突 | 当前编辑成为主文件；原磁盘及另一版本各保留副本 |
| 打开审阅后外部再次修改 → 尝试解决 | 拒绝覆盖新内容，保留冲突，显示重新审阅的明确操作说明 |
| 重新审阅 → 全部保留 | 成功，审阅期间新增的内容也保存在副本中 |
| 取消冲突审阅 / 取消移动预览 | 返回原界面，无写入 |
| 横屏冲突操作、滚动差异、竖屏键盘 | 按钮可触达；差异可滚动到末尾；无观察到的溢出 |

## 实测发现并修复

- iOS 不支持 `dart:io` 文件监听，导致目录树直接报错：改为原生工作区事件和恢复前台刷新。
- Tooltip 抢占长按，菜单难以打开；桌面主题导致触屏控件过小：修正手势和平台主题，文件行至少 44、菜单项 48 逻辑像素，手机不启用桌面拖拽。
- 目录变动与异步展开竞争时显示临时失效错误：对同一目录的有效请求有限重试。
- 原生 Trash 中的项目未能从 iOS Files 找到恢复入口：改为工作区内可见的“最近删除”，确认框解释恢复方式，按唯一日期目录保存且不自动清理。恢复通过长按项目 → Move to… 完成。
- 删除后的目录树不立即出现回收目录：操作完成后触发刷新。
- 本机回退工作区错误标成 iCloud：使用原生工作区实际名称和来源。
- 冲突审阅过期展示原始 PlatformException：原生提供明确错误码，界面说明未覆盖新内容及重新审阅步骤。
- 移动预览中的完整沙盒路径挤占手机界面：内部路径相对显示，外部目标显示末级目录和文件名，实际目标不变。

正常文档没有持续刷新的 iCloud 状态。只有需要处理的冲突进入提醒与解决流程。
