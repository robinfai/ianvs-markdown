## 明确拒绝的改动

- **不放大所有 shell 图标。** 规范明确将 glyph 和命中区域分开；新建、侧栏、右大纲等 header 控件已是 28 点，标签关闭也是 28 × 28。截图中小图标不等于命中区域缺陷。
- **不重复加 New/Open 工具栏入口。** 当前标签栏已有新建，原生菜单承担文件操作；增加重复入口会破坏现有单一位置约定。
- **不改黑色侧栏、不引入新强调色、不重新分配左右栏。** 这些都是明确设计约束，当前截图没有支持整体改版的证据。
- **不把所有模式名改为长句。** 保留紧凑的 Live / Source / Read，解释放在 tooltip 与辅助功能名称，避免占满工具栏。
- **不宣称已满足 VoiceOver。** 本轮未运行 VoiceOver。截图与代码语义只能为下一轮及回归检查提供方向。

## 第二轮审查要点

1. 确认模式文案与功能真实行为一致，尤其 Read 确实不可编辑；确保 tooltip/semantics 的解释不会重复冗长播报。建议文案：`Live Preview — edit with inline formatting`、`Source — edit Markdown source`、`Read — preview without editing`。
2. 中英文、emoji、长文件名和文本缩放下，实际测量的标签宽度与 selection reveal 使用相同结果；关闭按钮、dirty indicator 不导致文本或标签突然抖动。只有测量修正有证据时再改，不改变最大标签宽度策略。
3. 已取得 Source 空白文档真实截图，补查 Live、Read 空白态。已有提示则保留；若 Read 的空白态需要说明，应使用只读文案，不复用可编辑提示。Source 新提示要验证首次输入、删除回空、切换模式、保存空文件时均不改变内容。

建议三项均进入第二轮，其中模式 label 与 Source 空白提示已有当前运行证据，字宽方案有代码依据但应先用当前运行态复核收益。完成两轮前不调整产品 UI。
