# Linefold 用户体验与功能审阅

日期：2026-09-22。对象：本工作区 macOS Linefold 调试应用及其 ianvs_markdown 组件。方法：通过电脑工具实际操作原生应用，结合当前源码、回归测试和保存后的截图复核。

## 结论

新建、打开、工作区搜索、三模式编辑、保存、外部文件变更恢复、标签页和大纲已经形成可用的日常写作流程。Markdown 的基础排版、列表、任务、表格、代码、公式、脚注和部分 Obsidian 语法较完整。

目前最明显的产品缺口是“可见外观与实际动作不一致”：链接看起来可点击，桌面宿主尚未接入导航；图片、Wiki 嵌入、Mermaid 只到占位或源码层。它们属于桌面集成缺口，不能因为组件提供了回调，就记为桌面功能完成。

本轮完成了两轮 subagent + 内置 imagegen 设计评审后的小范围 UI 调整；另外修复了真实操作发现的主题切换渲染错误。完整的入口、语法和边界见 [功能矩阵](feature-matrix.md)，检查命令和覆盖限制见 [验证记录](validation.md)。

## 真实用户路径

| 路径 | 实际操作与结果 |
| --- | --- |
| 从空白开始 | 新建空文档，切换 Live / Source / Read；两个编辑模式显示轻量写作提示，Read 不显示写作提示。状态仍为 0 words / 0 characters，提示不进入正文。 |
| 打开工作区 | 使用原生目录选择器打开体验目录；展开 fixtures 和 Nested，搜索中文“目标”，结果显示相对路径并能打开目标文件。无匹配时提供空结果状态。 |
| 编辑一篇混合语法笔记 | 逐段检查中文、英文、emoji、换行、行内样式、列表、任务、引用、Callout、代码、表格、公式、脚注及 HTML 子集；Live 点击普通段落前后布局保持稳定。 |
| 任务与表格 | 勾选任务后撤销恢复；表格单元格“可用”改为“已检查”后撤销，正文和 Saved 状态恢复。表格列宽会随内容明显变化，仍有体验改进空间。 |
| 保存与外部冲突 | 新建草稿、取消保存、再次保存成功；新文件出现在文件树。外部写入触发变更条；Reload 后撤销能找回完整本地草稿。验证只使用本轮样本。 |
| 长文导航 | 40 节、6517 字符样本：Live 大纲跳到第 39 节，Read 跳到第 40 节，Source 返回第 1 节。末尾受滚动边界限制会同时露出上一节，目标仍可见。 |
| 文件格式 | 打开 UTF-8 / CRLF 样本，Source 追加中文和 emoji 后保存；磁盘字节保留 3 处 CRLF，未产生孤立 LF。此结果不代表所有粘贴来源与混合换行组合。 |
| 外观与窗口 | 检查浅深外观、正常窗口与放大窗口；实际复现了切换主题丢标题、任务状态错误的问题，修复后再次切换并确认显示恢复。 |

## 本轮已修复

| 项目 | 用户遇到的问题 | 修改与验证 |
| --- | --- | --- |
| 主题切换 | Read 模式切换深浅主题后标题消失，进行中、疑问任务被显示成已完成。底层图片回调的源索引也会随重复解析累加。 | 修正 Markdown 重复遍历时的标题、任务、图片源索引。先用两项测试重现失败，再验证通过；真实深色界面保留标题及四类任务。 |
| 中文标签宽度 | 按字符数估算使较短的中英文混合文件名也被省略；窗口收窄后当前标签可能在视口外。 | 用实际字体测量宽度，标签布局与选中标签滚动共用结果；窗口尺寸变化后重新显示当前标签，保留既有 92–220 范围。 |
| 模式可理解性 | Live / Source / Read 只有短文案，辅助功能状态和用途解释不足。 | 保留短文案，补齐完整名称、button、selected 和 tap 语义及用途 tooltip；点击区域最低 28 点。测试确认辅助技术操作能切换模式且不改正文。 |
| 空文档入口 | 空白编辑画布缺少开始输入的提示。 | Live / Source 加入“Start writing Markdown…”；整份文档为空才出现，不计入正文、字数、保存或 dirty 状态。Read 保持阅读语义。 |
| 文档描述 | 根 README 仍描述旧 Bear / 珊瑚色 / 悬浮大纲方案。 | 更新为当前黑侧栏、中性亮暗、蓝色操作强调和停靠大纲，并在 app README 写明宿主集成边界。 |

## 尚需产品决策或后续实现

优先级是本轮体验建议：P1 表示会阻断已被界面暗示的常用动作；P2 表示明显摩擦或未提供的常见能力；P3 表示偏好与完善项。

| 优先级 | 现象、证据与影响 | 建议及验收条件 |
| --- | --- | --- |
| P1 | 外部链接、本地笔记、页内锚点、Wiki、标签和脚注导航没有接通。实点外部、本地、页内和脚注入口未产生预期导航；EditorShell 未传 onTapLink。 | 在桌面宿主实现按目标分类的导航；验收外链打开、本地路径解析、重复标题锚点、块 ID、脚注往返和不存在目标的反馈。 |
| P1 | 本地图片显示“Image blocked · local”；Wiki 嵌入只显示引用；Mermaid 显示代码。宿主未传相关 builder。 | 接入工作区资源解析和明确的远端加载策略；再验收相对路径、尺寸语法、错误反馈、图片查看与缩放、笔记嵌入和图表渲染。保留组件默认不做 I/O 的边界。 |
| P2 | 表格第二列增加一个汉字后，列宽从接近均分变成中间列占大部分空间，撤销时又回跳。见 08 / 09 截图。 | 先确定与现有 Obsidian 列宽规则的取舍；若要提高编辑稳定性，可在当前编辑会话中固定或平滑调整列宽，再评审实施。 |
| P2 | 行内单行 details 示例在 Read 中不显示；当前实现只覆盖特定多行 details 结构，不是通用浏览器 HTML。 | 在兼容说明中列出支持的子集；若要支持单行 details，增加独立解析与可访问性验收，避免将“HTML 支持”表述为完整支持。 |
| P2 | 搜索只针对文件名；没有文内查找替换、全文检索或导出入口。 | 按写作场景排序建设。优先文内查找和替换，并区分搜索文件与搜索正文。 |
| P2 | app 隐藏了组件格式工具栏，菜单也没有完整格式命令；新用户难以发现表格、链接、代码等编辑能力。 | 根据目标用户决定格式菜单或命令入口；不在本轮自动扩增工具栏。 |
| P3 | 外观不跨启动保存；会话保存文本、模式、路径和侧栏状态，但没有序列化光标与滚动位置。 | 如果目标是重启后继续原位写作，把偏好与文档视图位置加入独立会话字段并测试缺失字段迁移。 |
| P3 | 状态栏 UTF-8 / LF / CRLF 是显示项，尚无格式转换控件；字数按当前实现计算，不应理解为中文分词计数。 | 明确“字符”和“字数”的定义；只有在支持转换后再提供可操作的编码/换行入口。 |

## 两轮设计评审与执行顺序

1. 第一位 subagent 基于现有产品规范、当前运行截图和代码生成方案图并审阅：[评审](design/round-1/review.md)、[完整提示词](design/round-1/prompt.md)、[方案图](design/round-1/mockup.png)。
2. 第二位 subagent 审阅第一轮方案、当前截图和实现位置，使用内置 imagegen 生成收敛稿，给出可实施边界：[评审](design/round-2/review.md)、[完整提示词](design/round-2/prompt.md)、[方案图](design/round-2/mockup.png)。
3. 两轮结束后才修改产品 UI。Live 空态还取得新的真实截图，并由第二轮评审补充确认后才加入提示。Read 不加入写作提示。
4. 保留 app/DESIGN.md 的工具栏、标签栏、侧栏、大纲尺寸和色彩约定。生成图仅作为设计讨论材料；其中字号、间距、模拟光标和注释标记没有直接照搬到产品。

两轮都使用内置 imagegen，输出已复制到本工作区。实际验收使用运行截图、AX 状态和测试，不用生成图证明功能通过。
