全部 JSON 汇总已逐项核对逐样本 JSONL：样本数、预热数、解析次数与延迟一致。
低样本、缺少操作、未完成及百分位与原始值不符的数据会被拒绝。

性能采样使用临时 SDK 补丁隔离上游 macOS profile AOT 问题，详见
[运行方法](README.md#macos-aot-prerequisite)。该补丁未进入日常 SDK；本报告
记录受控组件测量。未修改 SDK 的分析、单元测试和 Debug 构建由 CI 单独验证。

schema 2 将原先混合的模式切换拆成三个方向，并按引擎帧时间归属 frame 数据。
[旧 schema 1 报告](VALIDATION-2026-10-07.md) 保留当时 29/30 阶段的历史结果；
两个版本的绝对耗时不作直接比较。旧失败没有逐样本记录，不能据此精确还原
某一次切换。新完整运行确认所有单次动作都能完成，同时保留了慢切换的实际成本。

## CPU 诊断与优化方向

独立诊断使用同一最低 SDK，在 1 MiB 无预算的 Live → Source 测量区间采集
4,134 个 CPU 样本，采样周期 1000 µs；该次动作耗时
6261.3 ms。它仅用于归因，未混入上面的正式延迟配对。采样覆盖 UI isolate，
部分调用栈被截断；样本占比不等于整个进程或墙钟时间占比。

- Skia `ParagraphImpl::applySpacingAndBuildClusterTable` 的独占计数为
  3097，占样本约 74.9%。
- `buildMarkdownSourceTextSpan` 的包含计数为 301，约
  7.3%；包含计数可能重叠，不能相加当作 CPU 时间占比。
- 该方向的已验证热点是源码文本排版。R2-01 应同时评估样式分段、布局预算与
  解析复用，保留选区、IME 和源码保真契约。完整序列中 Reading 的耗时也需
  单独采样归因，不直接套用源码模式的 CPU 结论。
